# Phase 2 plan

## Decisions that block work

- **Labels and references.** Choose the independent analyst or analysts, adjudication process, and labelling format or tool for 200 stock × KPI pairs across three themes, 100 flawed scores, and 500 relevance labels across three themes. The existing 200 AI labels are provisional and cannot satisfy the release gate. Choose the remaining themes and 3–5 reference ETFs or indices. GRID holdings dated 2026-11-20 are already frozen for Smart Energy; use the intersection with the selected universe and disclose its scope limitations.
- **Gate 2 authority.** Decide single or two-person sign-off, who can approve and override, how identities are established locally, and when a basket is final. Decide how existing immutable provisional baskets are presented or replaced. A Reviewer pass alone must not silently relabel them.
- **Reviewer.** Select a model and pinned provider on a different vendor from every effective scoring route, including the current Jev-first route and OpenAI Luna fallback. Decide whether to evaluate Jev as an additional Reviewer or pre-screen candidate, not assume it qualifies as an independent Reviewer. Establish eligible routing and costs before live evidence is sent.
- **Budget.** Agree a per-run budget and confirm the monthly OpenRouter cap and remaining balance. The Phase 1 account cap was $50, not a per-run limit; the spec's under $30 is a target, not an agreement. Agree the cost and duration model, including ingestion, embeddings, retries, review, cache misses, Jev calls, provider rate limits and concurrency, and whether human wait time is excluded from the four-hour machine-time measure.
- **Universe and market cap.** Decide whether the full universe is US only or also EU, UK and Switzerland, and define point-in-time market cap, share-count availability, cutoff and missing-data policy. Phase 1 chose EODHD EOD prices and volume, ECB FX, SEC shares for US names, and observed Yahoo shares and caps elsewhere. Yahoo snapshots support today, not historical backtests. EODHD remains optional; record coverage gaps and the personal-use restrictions in the Phase 1 plan.
- **Replay contract.** Agree the canonical outputs and inputs for Phase 2 cache-only replay, including timestamps, IDs, human decisions, and uncached Jev decisions. A missing cached response must fail closed; decide whether to record Jev responses for replay or block runs containing them. Phase 5's byte-for-byte reconstruction of a past run from stored records is a separate, stronger promise.
- **Hosting and privacy.** Confirm that local hosting remains acceptable for the full run and decide any residency requirements. Phase 1 recorded operator privacy sign-off and account settings for Jev, but EU in-region routing was unavailable and a filtered request does not independently verify retention. Recheck current model and provider eligibility and account controls for the chosen routes before sending evidence. Select a host only if local hosting is insufficient.
- **Pre-screen.** Decide classifier type, threshold and treatment of missing evidence, and approve the validation population and recall target. The spec requires at least 95% recall on 500 labels across three themes; the embedding cut and classifier must be evaluated together against that set before reducing roughly 3,000 names to roughly 300. The existing embedding choice is `openai/text-embedding-3-small` on Azure through the gateway, subject to current eligibility. Jev is an optional candidate, not a selected classifier.

## Check protocol

Each PR has unit, live and performance checks. Unit checks use recorded fixtures and never call paid APIs. Live checks exercise the actual local CLI, service, database or browser. Record exact commands, fixture versions, inputs, environment and results in the PR. A fixture run does not satisfy a provider or phase live gate. Label-dependent live checks are BLOCKED until the independent labelled data exists. Provider checks are BLOCKED without credentials, approved privacy settings and budget.

For every perf check run the same command on trunk first on the same machine and input, then run three warm repetitions on trunk and the branch and record each median. If trunk lacks the operation, record `not applicable: capability absent` and use the absolute ceiling as the first baseline. Fail on a median regression greater than 25% or the stated ceiling. All per-PR ceilings below are provisional gross-regression limits, not provider latency or acceptance targets. New commands below are deliverables of their PRs, not existing commands. `bun run test` is required before each PR finishes.
